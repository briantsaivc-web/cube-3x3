2. **跑 `test:ui` 會覆寫 `docs/qa/shots/`**：本輪有 11～12 張截圖出現差異。iPad 的截圖因為字級變大，本來就會不同；`phone-09`、`phone-27-*` 推測是動畫時間點不同造成的雜訊。本角色不能改 docs/，所以每次跑完都先把新截圖備份到 `scratch/s13/ui-shots-run2/`、`ui-shots-final/`，再用 `git checkout -- docs/qa/shots` 還原。下次 QA 重跑時會重新產生。
3. **根目錄 `index.html` 已重新建置**：驗收條件要求跑 `node build/bundle.js`，UI 測試也讀根目錄的 index.html。現在的 index.html 是修正後的版本（sha256 `795e31ec…`，原本是 `6fa3a005…`），工作區顯示為已修改。index.html 屬於 release-manager 的建置產物，是否以這份為準由發布流程決定。
4. **build 大小增加 8,366 bytes**（372,477 → 380,843），主要是新增的繁體中文註解。距離 D-13 的 400 KB 上限剩約 19 KB，之後改版需要留意。
5. **主執行緒 watchdog 的保護範圍有限**：主執行緒上的計算是同步的，watchdog 無法中斷正在進行的求解，只能處理「排了程卻沒有執行」的情況；實際的計算量上限仍是 NODE_LIMIT。這點已寫在 `solver-client.js` 檔頭。
6. **hint-view 送出結果的順序**：`requestHint().then` 仍然先呼叫 `showFailure`、再 dispatch，與 demo-player 在 B-1 之後「先 dispatch」的順序不同。如果 `showFailure` 丟例外，state 會停在等待中；這個情況現在可以用等待卡的「取消」（T-UI-37 的備援）離開，但我沒有調整順序。建議下一版一併處理。
7. **同一段 CSS 附近還有其他小於 14px 的文字**：`.kp-caption`、`.kp-caption-toggle` 是 12px，本輪沒有改動。如果要放大，可以直接加進同一段 `@media (orientation: landscape) and (min-width: 1000px)`。QA Minor-1 列出的其他小字（`.k` 11px、`.hint-prompt` 12px、`.ctl` 13.5px 等）也都沒有改動。
8. **iPad 直向（768×1024）仍是 10px**：這個版面下每顆鍵寬約 119px，空間足夠放大；不過它套用的是直向（手機）版面，不在本輪範圍內。
9. **reviewer 的 `cr-solver.js` 使用的假計時器不看延遲時間**：它會依登記順序執行所有計時器。第一版修正先登記 watchdog，導致這支腳本得到「逾時退回層先法」的結果。已改成先登記排程、再登記 watchdog；真實計時器依時間排序，行為不受影響。改完後已在最終版程式上重跑全部驗收（§3.1）。
