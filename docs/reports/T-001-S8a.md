## 介面契約（供 S8b／S8c／S8d 開工依據）

### `ctx` 完整欄位

由 `app.js` 建立並依序呼叫各模組 `mount(ctx)`（`cube-view.js` 先掛，因為它會設定 `ctx.view`／`ctx.anim`，其餘模組可能依賴）：

```js
ctx = {
  root,        // #app 的 DOM 元素
  data,        // window.GAME_DATA（texts/palette/params/lbl），?test=1&tutorial=0 時 params.tutorial.enabled 會被覆寫為 false
  engine,      // require('../engine/index.js')：cube + reducer + selectors 全部函式
  notation,    // require('./notation.js')：fillTemplate/keySubLabel/keyAriaLabel/explainMove
  getState(),  // 目前 engine state（唯讀，勿修改回傳物件）
  dispatch(action), // 呼叫 engine.reduce；action 被 REJECT 時只吞掉例外，不 throw、不崩潰
  subscribe(fn), // state 改變後呼叫 fn(newState)；回傳 unsubscribe()
  panel,       // 見下
  input,       // 見下
  slot(name),  // 見下
  solver,      // 見下（包裝 S6 的 solver-client）
  view,        // 見下（cube-view.js 建立）
  anim,        // 見下（cube-view.js 建立）
  newGame()    // 【額外便利欄位，非規格必要契約】：產生 seed 並 dispatch NEW_GAME，並播放打亂動畫（§11.4）；
               // 目前只有 controls.js 的「打亂／再來一局」按鈕使用，S8b～S8d 應不需要它
}
```

### `ctx.panel`

- `selectTab('controls'|'demo')`、`currentTab() → string`
- `expand(on)`、`expanded() → boolean`（手機抽屜；iPad 呼叫仍會記錄狀態，但 CSS 在橫向一律強制顯示分頁內容，不受 `expanded` 影響）
- `onChange(fn)`：分頁或抽屜狀態改變時呼叫 `fn()`（無參數，請自行 `currentTab()`/`expanded()` 取值）
- `controls.js` 已實作：操作列「看電腦解」→ `selectTab('demo')` + `expand(true)`（不送 action，X-16）。**S8c 的 `demo-player.js` 需自行監聽 `ctx.subscribe`，在 `demo` 由非 null 變 null（`DEMO_EXIT`）時呼叫 `ctx.panel.selectTab('controls')`**（分派單 §3 S8a 輸出契約寫「`subscribe` 偵測 demo 由非 null 變 null 時 selectTab('controls')」，本段已規劃由 S8c 一併處理，因為 S8c 才知道 `DEMO_EXIT` 的時機；若 systems-engineer 認為此職責應留在 S8a，請回報，目前 app.js／controls.js 未實作此自動切回，屬**待確認項**，見下方「未預期發現」）。

### `ctx.input`

- `lock(owner)`、`unlock(owner)`、`locked() → boolean`（`owner` 為任意字串，多個鎖並存用 `Object.keys` 計數；本段的打亂動畫用 `'scramble-anim'` 作為 owner）。
- 所有會動畫或送 `TURN`/`ROTATE` 的模組（手勢、記號鍵、示範自動播放、記號小教室）都必須在動作前檢查 `ctx.input.locked() || ctx.anim.busy()`。

### `ctx.anim`（`cube-view.js` 建立）

- `turn(viewMove, ms) → Promise<void>`：只做「畫面」局部層轉動動畫（呼叫 `engine.layerStickers(viewMove)` 找出受影響的 cubie，暫時搬進一個轉場用 wrapper 並套用 CSS `matrix3d` 動畫）；**不會自己 dispatch action**，呼叫端動畫完成後要自己送 `TURN`。動畫結束到下一次 `render()`（即下一次 `ctx.subscribe` 觸發）之間，畫面會維持在動畫結束的姿態（不閃爍），所以呼叫端應該「animate 完 → 立刻 dispatch」，不要延遲。
- `rotate(rotation, ms) → Promise<void>`：整顆旋轉（`x y z` 系列）的動畫，其餘同上，呼叫端動畫完成後自己送 `ROTATE`。
- `busy() → boolean`：任一 `turn`/`rotate`/`previewTurn` 動畫進行中即為 true。
- 旋轉方向已用 3×3 矩陣依 engine 座標（rotateCw ⇒ −90°）換算成 CSS 座標（y 軸相反的鏡射，角度需連同取反，詳見 `cube-view.js` 檔頭與 `rotationMatrixCss` 註解）；**已用「點按 R/U/M 後 `home` 與 engine 直接運算結果比對」驗證最終姿態正確**，但動畫「過程」方向未逐一人工核對每個記號（36 個都用同一套矩陣公式生成，理論上一致；若日後真機看到某些記號動畫方向感覺相反，請先查 `AXIS` 表與 `rotationMatrixCss`，而不是重寫個別記號）。

### `ctx.view`（`cube-view.js` 建立）

- `projectAxes(viewIndex) → {right:{x,y}, down:{x,y}}`：取該貼紙所在面的「右」「下」方向，投影到目前基準視角（`params.ui.baseViewDeg`）下的螢幕座標（**只套用固定基準視角，不含拖曳中的暫時旋轉**；螢幕座標系 x 右、y 下，與滑鼠位移座標系一致，S8b 可直接拿來與 `pointermove` 的 dx/dy 做內積判斷方向）。
- `setDragRotation(matrix)` / `clearDrag()`：`matrix` 是**攤平的 9 個數字（3×3，列優先）CSS 座標旋轉矩陣**（不是 4×4、不是角度對），代表「疊加在基準視角之上」的暫時旋轉，用於拖曳整顆方塊時的即時視覺回饋。`clearDrag()` 會把 `.cube-world` 的 transform 清空並立刻依目前 state 重畫。
- `nearestOrient(matrix) → 0..23`：同樣吃 9 個數字的 3×3 CSS 矩陣，回傳與 24 種朝向對應之相機旋轉矩陣中最接近的 orient 編號（用 `trace(R1ᵀ·R2)` 最大化，標準旋轉距離度量）。
- `snapTo(orient, ms) → Promise<void>`：把 `.cube-world` 從目前的 transform 動畫到 `orient` 對應的相機矩陣；**動畫結束後呼叫端要自己 `dispatch({type:'SET_ORIENT', payload:{orient}})`**，之後畫面下一次 `render()` 會把 `.cube-world` 重設回單位矩陣（因為朝向已經改用貼紙顏色置換表示，見下段原理說明）。
- **額外提供**（非規格必要契約，方便 S8b 組矩陣）：`ctx.view.multiplyMatrix(a, b)`、`ctx.view.axisAngleMatrix(axisCss, angleDeg)`（皆吃／回傳攤平 9 數字矩陣）。
- `highlight(indices)`：`indices` 為 view 座標貼紙索引陣列（0–53）；傳 `[]` 清除。每次呼叫會先清掉前一次的高亮再套用新的。
- `setFaceLabels(on)` / `faceLabels() → boolean`：面標籤開關（§11.2）；六個中心固定顯示位置代號（**跟位置、不跟顏色**，索引 4/13/22/31/40/49 → U/R/F/D/L/B，永遠不變，因為 view 座標本來就是「玩家目前看到的方塊」，跟顏色置換無關）。
- `onFaceLabelsChange(fn)`【S8e／D-19 新增】：`setFaceLabels(on)` 呼叫後（不論呼叫端是誰）會依序呼叫所有以 `onFaceLabelsChange` 註冊的 `fn(on)`。用途：面標籤開關是**跨模組共享狀態**（`controls.js` 的 `#faceLabelToggle` 開關、`tutorial.js` 的教學期間強制開啟／結束後還原都會呼叫 `setFaceLabels`），S8d 曾經另外寫一份「把 `#faceLabelToggle` 的 `aria-checked` 手動同步」的小工具來補這個洞（見 `docs/reports/T-001-S8d.md`）；改用這個訂閱介面後，任一模組呼叫 `setFaceLabels` 都會讓其他模組（目前是 `controls.js`）同步 `aria-checked`，`tutorial.js` 不需要再自己維護一份同步邏輯。沒有 `offFaceLabelsChange`（目前只有 `controls.js` 這一個訂閱者，全生命週期存在，無需取消訂閱）。
- `previewTurn(baseStickers, viewMove, ms) → Promise<void>`：**不碰 state**，以 `baseStickers`（54 色號陣列）為起點播放一次轉動動畫，動畫結束後畫面停在 `engine.applyMove(baseStickers, viewMove)` 的顏色（不是目前 state 的顏色）。呼叫端可連續呼叫（把上次回傳的顏色當下一次的 `baseStickers`）串成一整段預覽序列（`app.js` 的打亂動畫、S8d 的記號小教室 L 步示範都用這個模式）。
- `clearPreview()`：結束預覽模式，畫面立刻依「目前真正的 state」重畫。**進入 preview 模式後，在 `clearPreview()` 之前，畫面不會反映真正的 state 變化**（`ctx.subscribe` 的 render 仍會被觸發，但會畫 preview 的顏色，不是 state 的），示範播放器（S8c）與教學（S8d）務必在每次「離開」時呼叫 `clearPreview()`，否則畫面會卡在預覽畫格。

**運作原理提醒（避免誤解／誤改）**：`orient` 在 engine 裡是靠「把 54 格貼紙顏色置換過」表示朝向改變的（`viewStickers = applyOrient(home, orient)`），**不是**靠 CSS 把整顆方塊轉過去。所以正常渲染（`render()`）時 `.cube3d` 只有固定的基準視角、`.cube-world` 永遠是單位矩陣，六面的「螢幕位置」永遠不變，變的只是每個位置上的顏色。`ctx.anim.rotate`／`ctx.view.setDragRotation`／`snapTo` 做的「整顆旋轉動畫」只是**過場**用的暫時視覺效果，動畫一結束、下一次 `render()` 就會把 `.cube-world` 重設回單位矩陣，靠新的顏色置換去呈現「看起來轉過去了」的結果。S8b 寫手勢時如果忘記這點、試圖讓 `.cube-world` 在靜止狀態下也保留旋轉，會跟 `render()` 的重設邏輯打架。

### store／action 慣例

- `dispatch(action)` 內部呼叫 `engine.reduce`；action 被 `REJECT:*` 拒絕時**只是不改變 state、不呼叫 listeners**，不會 throw 到呼叫端。呼叫端不需要自己包 try/catch。
- 所有帶 `at` 的 action（`TURN`、`UNDO`、`REDO`、`PAUSE`、`HINT_REQUEST`、`DEMO_REQUEST`、`DEMO_STEP`、`DEMO_SEEK`、`DEMO_EXIT`）請用 `performance.now()`（`app.js`／`controls.js`／`cube-view.js` 皆有本機 `nowMs()` 小工具，各檔各自一份，避免互相 require）。
- `NEW_GAME` 的 seed 一律呼叫 `ctx.newGame()`，不要自己產生 seed（§5 規定 seed 只在 UI 層產生一次的位置）。
