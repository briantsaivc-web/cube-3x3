## 4. 未預期發現

- `game-spec.md` 只明確定義了少數幾個拒絕原因字串（`invalidSeed`、`notATurn`、`badReason`、`stale`），其餘 action 的拒絕原因（例如 `demoActive`、`hintPending`、`noHistory`、`noRedo`、`notPending`、`invalidTokens`、`invalidKind`、`missingSegments`、`notReady`、`invalidDelta`、`outOfRange`、`noDemo`、`alreadySolved`、`invalidOrient`、`notARotation`、`noHint`、`unknownAction`）規格未點名，屬工程判斷自訂。`T-ENG-22` 只要求「格式為 `REJECT:<TYPE>:<reason>`」與「`canApply` 與 `reduce` 判斷一致」，不要求特定字串，故不影響驗收；若 UI（S8*）或求解流程（S6）需要依賴特定拒絕原因字串做分支，請 systems-engineer 確認是否要把這份自訂清單正式收進規格，避免各段各自猜測。
- `selectors.js` 的 `demoInfo(state).segmentIndex`／`partIndex` 在「已播完最後一段」（`cursor === segments[last].end`）時的行為，規格 §4.1、§8.2 沒有明講；本段實作為「停留在最後一段」（`segmentIndex = segments.length - 1`），理由是 UI 需要在播完時仍能顯示「第幾段」而非變成 `-1`。若與 S8c 的分段暫停卡片設計不符，請回報調整（屬本段 `selectors.js` 的小修，不影響 state 契約）。
