### 輸出契約（給 S6）

```js
generateLbl(viewStickers54, config) → {tokens, segments, qtm}        // §8.2 格式
                                    | {error, detail}
// error：'LBL_STUCK'（迴圈超過上限，或某段結束時完成判定不成立，detail = 'check:<段id>'）
//        'INVALID_STATE'（長度或色號錯、中心重複、找不到某邊塊或角塊；detail 用 spike 錯誤碼 LENGTH／BAD_COLOR／CENTER_DUPLICATE／EDGE_UNKNOWN／CORNER_UNKNOWN）
//        'BAD_REQUEST'（config 格式錯：segments 順序、公式缺漏或無法解析、guards 不是正整數、headlightFace 不是 F/R/B/L、firstLayerColor 超出範圍）
STAGE_CHECKS[id](stickers54, config) → boolean    // 8 個，鍵的順序與 segments 相同
// 附加匯出（測試與診斷用，UI／Worker 不需要）：
generateLblDetailed(view, config) → {result, loops} | {error, detail}   // loops = 本局各迴圈的實際次數
SEGMENT_IDS, GUARD_KEYS
```

- `part.kind` 的實作方式：
  - `setup` 一律是**單一外層轉動**（照 §8.2 的定義）。所以 cross 段的 `t D t⁻¹` 會輸出成 3 個 setup part；原型是合成 1 個 part。
  - 連續的整顆旋轉會併進**同一個** rotate part，再合併同字母旋轉。例：corners 段的「y 對位目標槽」緊接「y 把角塊帶到 UFR」，兩者會合成一個 part；合併後互相抵消時，這個 part 直接刪掉。
- `guards` 怎麼計數：
  - `cross`、`corners`、`middle` 算的是該段的**迴圈輪數**。
  - `cornerInsert` 算的是**每個角**套用了幾次。
  - `yellowCross`、`sune`、`aPerm`、`uPerm` 算的是該公式**套用了幾次**。
  - 已經達到上限還需要再做一輪時，回傳 `LBL_STUCK`。
- 單次產生的耗時（Node v22.22.2，40 記號序列 1,000 局，暖機之後量）：平均 0.210 ms、p95 0.219 ms、最大 24.4 ms。最大值只出現一次，推論是 GC 造成。

## 4. 未預期發現

1. **跨段的相鄰同字母整顆旋轉（hold → middle）。** 如果 cross 與 corners 兩段本來就完成（也就是第一層已好、白色在 L 或 R），hold 會輸出 `z`／`z′`，緊接著 middle 輸出 `z2`，變成相鄰的同字母旋轉。近復原樣本中共有 44 處（`z z2` 22 處、`z′ z2` 22 處）。
   - §8.1 規定「只在同一分段、同一個 part 內合併」，但 T-LBL-07 要求「輸出中沒有相鄰的同字母整顆旋轉」，兩條在這個情況互相衝突。
   - 目前的測試做法：段內一律不准出現；random／seq／末層三組連跨段都不准出現（實際 0 處）；近復原組只允許 hold→middle 這一種，並把次數輸出。
   - 待裁決，見 §5 第 1 點。
2. **已復原的方塊也會輸出記號。** 白色朝上的復原狀態會輸出 `["z2"]`（0 QTM）；黃色朝上的會輸出 `["x2","z2"]`。原因是 §8.4 規定 middle 段一律先輸出 `z2`。規格本來就這樣定，不是 bug；而且已復原時 UI 的示範按鈕依 §9.1 不能按。不過 S6／S8c 如果在已復原狀態下呼叫，會拿到非空的 `tokens`。另外，任何一局層先法解完，方塊都會變成**黃色朝上**（整顆朝向和開始時不同，但不計步）。
3. **規則本身會產生可以省下的步數。** 例：D 調整之後緊接 `crossFlip` 開頭的 `D`；U 調整之後緊接 `edgeRight` 開頭的 `U`。random-state 1,000 局中，相鄰的同面外層轉動共 6,693 處。規格要求公式 part 的記號必須完全等於 `lbl.json`，所以沒有合併，QTM 就照實計算（§8.5 的數字也是這樣算的）。如果要縮短示範，要改規格。
4. **setup 的切分與原型不同。** cross 段的 `t D t⁻¹` 拆成 3 個 setup part（§8.2 定義 setup 為單一轉動），UI 顯示「正在做」時會逐個顯示。
5. **錯誤碼比規格多。** §7.2 只寫 `{error}`；§9.5 錯誤表中，明文寫給層先法的只有 `LBL_STUCK`。本檔另外用了 `INVALID_STATE`、`BAD_REQUEST`，而且多帶一個 `detail` 欄位。這兩個碼都在 §9.5 的錯誤碼表內，S6 可以直接轉送；正常流程中，Worker 會先用 `fromStickerColors` 驗過輸入。
6. **測試的執行期依賴。** 「T-LBL-01 附帶」會在執行時載入 S4 的 `twophase.js`（唯讀，檔案不存在或無法使用時 skip），見 §3。
7. **`guards.cornerInsert`、`yellowCross`、`uPerm` 都等於實測最大值，沒有餘裕。** 目前的推論與全列舉都顯示它們已經是理論上限，所以不影響正確性；但如果以後改公式，要記得重新檢查。
