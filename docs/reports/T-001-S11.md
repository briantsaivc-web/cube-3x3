## 4. 未預期發現

1. **§9.6 的退回路徑，修好 B-1 之後仍然看不到（已修）。** `DEMO_FAILED` 讓 `demo` 從非 null 變成 null，觸發 D-15 的「切回操作分頁」，失敗訊息與「改看層先法示範」因此落在隱藏的分頁。改成只有示範曾經就緒時（離開示範、重設等）才切回，等待中被取消或求解失敗時留在示範分頁。T-UI-24 現在要求這兩個元素確實看得到，T-UI-15 的 `DEMO_EXIT` 切回檢查仍然通過。這屬於對 D-15 的解讀：D-15 原文只寫 `DEMO_EXIT`，請 systems-engineer 複審時確認。
2. **T-UI-19 手機視圖偶發失敗，原因在測試，不是產品。** 手機開頁或重新整理時，抽屜有 250 ms 的 `max-height` 展開動畫（`styles.css` 第 136 行，既有設計），記號鍵會從 y≈928 一路往上移到 708。測試用 `force:true` 點擊會跳過「等待元素靜止」的檢查，偶爾點到兩列鍵之間的空隙（`.kp-rows`）。
   - 實測：不加等待時 40 次有 3 次失敗；加上 `waitLayoutStable` 後 40 次 0 次失敗，T-UI-19 單獨跑 10 次也全過。
