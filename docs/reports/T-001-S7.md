## 4. 未預期發現

1. **HTML 註解裡若原樣寫出 `<!-- INJECT:CSS -->` 等標記字串會提前結束外層說明註解。** 起草 `index.template.html` 時第一版在檔頭說明註解裡逐條列出五個標記（含 `-->`），導致外層 `<!-- ... -->` 在第一個內嵌 `-->` 處就結束，後面的說明文字變成裸露在 `<head>` 外的文字節點，且會讓 `template.indexOf('<!-- INJECT:CSS -->')` 誤配到說明文字裡的那一份而非後面真正要被取代的標記。已在寫檔階段自行發現並改寫（說明文字改用非標記形式描述，不逐條列出含 `-->` 的字串），未進版控的錯誤版本沒有留下痕跡；記錄於此提醒 S8a 全面改寫 `index.template.html` 時留意同樣陷阱。
2. **Worker 字串的位元組數與字元數不同。** `window.SOLVER_WORKER_SRC.length`（JS 字串字元數，73,861）與 `Buffer.byteLength(...,'utf8')`（82,941）因原始碼含繁體中文註解而不同；`game-spec.md` §12.4 的 100 KB 上限應以位元組數為準，`build/bundle.js` 的 `checkWorker()` 與 `tests/engine/build.test.js` 都是用 `Buffer.byteLength` 計算，口徑一致。純屬確認，未發現問題，僅記錄避免日後有人誤用 `.length` 判斷大小。
3. **主產物比 §12.4 的推論值（約 200 KB）略大（221,876 bytes）。** 差距主要來自本段新增的 `src/ui/solver-client.js`（19,719 bytes，S6 產物）與 12 個 UI 空殼檔（合計約 100 bytes 量級，可忽略）進了主 bundle 的 `MAIN_FILES`——分派單本就要求 `solver-client.js` 進主 bundle 供主執行緒退回使用（ADR-001 §2.6），故此差距是預期範圍，仍遠低於 300 KB 上限，不影響驗收。
4. 過程中沒有誤改範圍外的檔案；未發現會影響 state 欄位、action、資料格式、24 朝向編號、RNG 呼叫方式或求解結果的問題。
