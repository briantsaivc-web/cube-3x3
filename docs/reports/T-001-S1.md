## 4. 未預期發現

- **`docs/spec/checks/` 是 `scratch/g3-check/` 的重複副本**（範圍外，未修改）：兩目錄內容幾乎完全一致（僅 `bench-nodes.js`、`cube-model.js` 兩檔不同），但 `game-spec.md` 附錄 A 明確記載這批 G3 驗證原型的正確位置是 `scratch/g3-check/`（且該目錄已列在 `.gitignore`，不進版控）。`docs/spec/checks/` 疑似先前操作誤植於 `docs/spec/` 之下，其中 `check-simplified.py` 內含完整簡體字字集字串（掃描工具本身需要），若依規格字面「全部 `docs/spec/` 無常見簡體字」逐檔掃描會被誤判為簡體字違規。
  - 本段處理方式：**未修改 `docs/`**（依共通規則不可碰），僅在 `tests/engine/data.test.js` 的 T-DATA-05 掃描邏輯中明確排除 `docs/spec/checks/` 這個路徑，並在程式註解中寫明原因。
  - 建議：請 systems-engineer 確認是否要刪除 `docs/spec/checks/`（保留 `scratch/g3-check/` 即可，且已被 `.gitignore` 排除版控），以免未來其他檔案掃描或審查誤判。
- 撰寫測試中曾一度誤將 `\uXXXX` 逃逸序列以 JSON 字串型式傳入寫檔工具，導致工具參數解析階段就把逃逸序列還原成真正的簡體字元、寫入檔案（已被 `check-simplified.py` 掃出並在完稿前修正）。最終版本改用「十六進位 Unicode 碼位陣列 ＋ `String.fromCodePoint`」的寫法，確保檔案原始碼與註解都不含任何簡體字元；記錄於此供其他段落（例如日後若有人也需要在測試檔存放簡體字表）參考，避免重蹈覆轍。
