## 三版一句話

| 版本 | 一句話定位 | 檔案 |
|---|---|---|
| A | 全螢幕沉浸式：方塊鋪滿整個畫面，操作用浮動圓形按鈕，記號鍵盤預設收在底部抽屜 | `v1-A.html` |
| B | 手機 App 式：頂部狀態列＋中間方塊＋底部固定操作列與記號鍵盤（常駐不收合） | `v1-B.html` |
| C | 學習導向：方塊固定在一側，另一側是「學習面板」（操作／示範兩個分頁），示範時分段資訊最顯眼 | `v1-C.html` |

## 差異對照

| 比較面向 | A 全螢幕沉浸式 | B 手機 App 底部操作列 | C 學習導向面板 |
|---|---|---|---|
| 資訊層級（玩家第一眼看到什麼） | 整個畫面幾乎都是方塊本身，計時／步數縮成頂部小藥丸，操作按鈕是畫面邊緣的浮動圓鈕，第一眼焦點 100% 在方塊上 | 頂部先看到標題與計時／步數列，方塊區塊清楚但只占畫面中段，底部操作列與鍵盤隨時可見，資訊分區明確 | 方塊與「學習面板」左右（iPad）或上下（手機）並列，第一眼會同時看到方塊與操作／示範分頁，暗示「這是用來學習解法的」 |
| 觸控動線（完成一次轉動要點幾下） | 記號輸入＝1 下展開鍵盤＋1 下按鍵＝2 下（鍵盤收合時）；若手勢直接劃方塊面則 0 額外點擊；提示／看電腦解都是 1 下浮動鈕 | 記號輸入全程 1 下（鍵盤常駐不用展開）；提示／看電腦解也是 1 下，操作最短 | 記號輸入常態 1 下（操作分頁常駐鍵盤，iPad 尤其方便）；手機直向若抽屜被使用者收起，需先 1 下展開抽屜才能點鍵盤＝最多 2 下 |
| 手機直向（390×844）表現 | 沉浸感最強、方塊最大最搶眼；但打亂／撤銷／重做／重設／提示／看電腦解六顆圓鈕垂直排一長串，靠右側拇指邊緣操作，最下面按鈕略靠近螢幕邊緣；記號鍵盤預設隱藏，新手可能一時找不到 | 版面分區清楚、上下捲動需求低，唯獨方塊置中區塊在手機上與鍵盤搶垂直空間，鍵盤 27 顆按鍵占去畫面下半約 4 成高度，方塊視覺上顯得偏小 | 方塊被壓縮到畫面上半約 48%，下方學習面板抽屜可展開／收合；預設展開時能同時看到方塊與示範資訊，但兩者都變小，是三版中「方塊＋資訊」同時可見但都不夠大的版本 |
| iPad 橫向（1194×834）表現 | 大螢幕讓方塊可以更大、浮動鈕與鍵盤抽屜也等比放大，沉浸感延續，但六顆圓鈕＋左下鍵盤鈕在寬螢幕上略顯零散，缺乏「面板」整體感 | 沿用手機的上下堆疊結構、置中限寬顯示，橫向空間大量留白（畫面兩側各留白約 27%），是三版中 iPad 利用率最差的 | 左右分欄天生適合橫向：方塊區占約 60% 寬、學習面板占約 40% 寬，兩者都有足夠大小，是三版中 iPad 利用率最好的 |
| 44×44 px 觸控目標是否全數達標 | 是（浮動圓鈕 60×60px／iPad 72×72px，記號鍵盤按鈕與鍵盤展開鈕均 ≥44px） | 是（操作列與鍵盤按鈕均 ≥44px，iPad 版限寬置中後按鈕大小不變） | 是（操作列、分頁鈕、鍵盤按鈕均 ≥44px；手機抽屜手把本身雖矮但點擊區含整條 handle 列） |
| 視覺風格 | 深色沉浸背景、白色浮卡與圓鈕形成強對比，最有「遊戲感」 | 淺色卡片式、橘色主色，最像一般手機 App，最不會嚇到不熟悉魔術方塊的玩家 | 淺色、方塊區與面板區有明確分隔線，最像「教學工具」而非遊戲 |
| 實作成本（game-engineer 預估） | 中：浮動定位＋抽屜動畫＋深色主題需要額外處理明暗對比，但沒有複雜的分頁邏輯 | 低：單純上下堆疊＋常駐鍵盤，沒有抽屜或分頁狀態要管理，是三版中最單純的 DOM 結構 | 高：需要維護「分頁狀態」＋「抽屜展開狀態」＋兩者連動（示範開始要自動切到示範分頁），手機與 iPad 的版面規則也不同（抽屜 vs 側欄），狀態最多 |
| 最大風險 | 記號鍵盤預設隱藏，若玩家不知道要點左下角圓鈕展開，可能誤以為「沒有備援輸入方式」，違反 CLAUDE.md「不依賴手勢才能完成操作」的精神（鍵盤仍然存在，只是多一步） | 手機直向方塊區塊偏小，且鍵盤／操作列常駐會讓「看電腦解」時的示範面板必須先擠掉鍵盤才有位置，示範開始那一刻畫面變化較大，可能讓玩家一時不知道發生什麼事 | 資訊密度最高、狀態最多，最容易在未來加新功能（如 2D 展開圖、知識卡）時變得擁擠；手機直向的方塊視覺尺寸是三版最小，若玩家主要用手機、又想看清楚方塊細節，可能不是最佳選擇 |

## 設計師建議（可建議，不可代選）

- 建議版本：**C**，理由一句話：本案定位「也能看電腦怎麼解（學習用）」，C 版把示範的分段名稱／說明／進度放在最顯眼的位置且 iPad（本案目標平台）利用率最好，最貼合「學習導向」這個核心賣點；代價是實作與狀態管理比 A、B 複雜，若工時吃緊，可先做 B（結構最單純）當可玩骨架，再把 C 的學習面板內容補上去（DOM 分區方式接近，遷移成本不高）。
- 若製作人想混合：建議「**C 的左右／上下分欄結構 ＋ B 的鍵盤常駐不分頁**」——即學習面板固定顯示操作區（不切分頁），只有按下「看電腦解」時才把面板內容換成示範資訊，兩者不並存但也不需要手動切換分頁，可以降低 C 版最大的風險（分頁狀態管理）。
